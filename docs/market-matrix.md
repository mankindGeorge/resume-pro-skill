# Market Matrix: Resume Conventions by Hiring Market

> These are **defaults, not laws**. Hiring conventions vary by company, city, industry, and year. The skill must state its assumption and let the user override. Never silently add sensitive personal fields.

## 1. Why one resume cannot serve every market

A resume is a selection and framing of facts for a specific reader. The same candidate is read differently by:

- a U.S. recruiter scanning for ownership and measurable impact in 5–20 seconds;
- a Chinese internet HR screen looking for school tier, big-company internship, and role fit;
- a Chinese SOE HR reviewer looking for stability, credentials, political status, and formal completeness;
- a design lead looking at portfolio and taste;
- an academic search committee looking at publications and research trajectory.

The facts stay the same. The **selection, order, wording, page geometry, and personal fields** change.

## 2. Market profiles

### A. `intl_en` — International / English (US, UK, CA, AU, EU)

| Dimension | Default |
|---|---|
| Language | English (US spelling for US; UK spelling for UK/EU) |
| Page | 1 page for < 10 years; 2 pages for senior/academic |
| Paper | A4 for browser printing |
| Photo | **No** |
| Personal fields | Name, city/region, email, phone, LinkedIn/GitHub/portfolio. **No** DOB, gender, marital status, nationality, ID number, full address, political status |
| Section order | Header → Summary (optional) → Skills (tech) → Experience → Projects → Education |
| Proof style | Action + scope + result; quantified; ownership explicit; no pronouns |
| Education | Degree, institution, dates; GPA only if early-career and strong |
| Self-evaluation | **Do not include** |
| Expected salary | **Do not include** |
| Photo/QR | No photo; QR rarely used |
| File | `Firstname_Lastname_Resume.pdf` |
| ATS priority | High: single column, standard headings, text-based PDF |
| Red flags | Photo, age, marital status, "responsible for", duties without results, buzzwords, multi-column layout, graphics carrying key text |

### B. `cn_internet` — Chinese internet / technology companies

| Dimension | Default |
|---|---|
| Language | Chinese (English only if the role requires it) |
| Page | 应届或 <3 年: 1–2 pages; 3+ years: 2–3 pages |
| Paper | A4 |
| Photo | Common and often expected; professional headshot |
| Personal fields | 姓名, 电话, 邮箱, 城市. Optional: 出生年月, 籍贯, 政治面貌. |
| Section order | Campus: 个人信息 → 教育背景 → 实习/工作经历 → 项目经历 → 核心技能 → 校园经历 → 荣誉/证书. Experienced: 个人简介 → 工作经历 → 项目经历 → 教育经历 → 专业技能 → 荣誉/证书. See `docs/cn-resume-rules.md` |
| Proof style | Result-first; data and scale; clarify personal contribution; FAB (Feature–Advantage–Benefit) |
| Education | School, major, degree, dates, GPA/rank, relevant courses for campus |
| School signal | 985/211/双一流 is often used as a filter; state it only if true |
| Internship signal | Big-company internship is the strongest campus signal |
| Self-evaluation | Common but should be evidence-based, not adjectives |
| Expected salary | Optional; often in the application form, not the resume |
| File | `姓名-岗位-学校.pdf` |
| ATS priority | Medium-high: single column, standard headings, text-based |
| Red flags | Empty claims, inflated ownership, no numbers, irrelevant old experience, template placeholder left in |

### C. `cn_soe` — SOE / government / public institutions

| Dimension | Default |
|---|---|
| Language | Chinese |
| Page | 应届或 <3 年: 1–2 pages; 3+ years: 2–3 pages; completeness often beats brevity |
| Paper | A4 |
| Photo | Expected; formal, conservative |
| Personal fields | 姓名, 性别, 出生年月, 籍贯, 政治面貌, 联系方式, 婚姻状况 (optional/only if requested) |
| Section order | 个人信息 → 教育背景 → 实习/工作经历 → 项目/科研 → 校园/学生工作 → 获奖荣誉 → 技能证书 → 自我评价 |
| Proof style | Formal, factual, stable, conservative; avoid exaggeration |
| Education | Full education history; degrees, majors, dates, honors |
| Political status | 中共党员/预备党员/共青团员 — only if true and relevant |
| Student leadership | 学生会/班干部/社团负责人 is a real signal |
| Certifications | 四六级, 计算机等级, 职业资格 |
| Self-evaluation | Expected; emphasize responsibility, stability, teamwork |
| ATS priority | Low-medium; human HR review dominates |
| Red flags | Informal tone, missing personal fields, job-hopping without explanation, typos, inconsistent dates |

### D. `cn_finance` — Finance / consulting (China and foreign firms in China)

| Dimension | Default |

### E. `cn_creative` — Design / creative / media

| Dimension | Default |

### F. `academic` — Academic / research CV

| Dimension | Default |
|---|---|

## 3. Hard transformation rules (EN ↔ ZH)

The rule is **transcreation from the fact vault**, not translation of rendered text.

### 3.1 Fields removed when going CN → EN

- Photo
- Date of birth / age
- Gender
- Marital status
- Nationality / ID number
- Full home address (keep city/region)
- Political status
- 籍贯
- 自我评价 (unless it contains a concrete professional positioning that can become a Summary)
- Expected salary
- 四六级 / 计算机等级 unless directly relevant to the role
- 到岗时间 (unless the application asks)

### 3.2 Fields added when going EN → CN

- Photo (only for `cn_internet`, `cn_soe`, `cn_finance`; ask first)
- Target role and city are used for targeting and file naming.
- 教育背景 with school/major/degree/dates/GPA/rank
- 校园经历 if the candidate is a student or new grad
- 荣誉奖项 / 技能证书
- 自我评价 (optional, evidence-based)
- 政治面貌 (only for `cn_soe`, only if true)

### 3.3 Content transformation

| Dimension | EN | ZH |
|---|---|---|
| Bullet logic | Action → scope → result | Result-first, then action and method |
| Ownership | Explicit "led / owned / built" | Clarify "独立负责 / 主导 / 参与" truthfully; never upgrade 参与 to 主导 |
| Metrics | Before/after, %, scale, time | Same facts; 万/亿 units; keep exactness |
| Education | Degree + institution; GPA if early-career | School + major + degree + GPA/rank + courses |
| Company names | Legal English name or transliteration + brief context | Chinese name + optional English |
| Job titles | Market-equivalent title; preserve original in parentheses if ambiguous | Standard Chinese title |
| Dates | `Mar 2022 – Present` | `2022.03 – 至今` |
| Spelling | US or UK per target | N/A |
| Tools | Keep product names untranslated | Keep product names untranslated |
| Summary | 2–3 lines, positioning + proof | 3–4 lines, positioning + strengths + intent |
| Page | A4, no photo | A4, photo optional |

### 3.4 Parity rules

A localized resume must pass a **fact parity check**:

1. Every employer, role, date, degree, certification, project, and metric in the source exists in the target, or is explicitly omitted with a reason and user approval.
2. No new employer, role, date, metric, award, or skill appears unless it exists in the vault.
3. No silent ownership inflation or deflation.
4. Unit conversions (e.g., 万 → 10K) are exact and flagged.
5. Semantic drift is flagged for review: a phrase that is "natural" in the target but changes the claim is a failure, not a translation.

## 4. Persona matrix

| Persona | Detected by | Section priority | Page | Primary proof | Template | Job recommendation |
|---|---|---|---|---|---|---|
| Student, no internship, no projects | `stage=student`, `internships=0`, `projects=0` | Education → Coursework/Competitions → Campus → Skills | 1 | Coursework, labs, competitions, campus roles, certifications | `campus` / `ats-classic` | Internships with lower technical bar; ops/support/sales/community; project-based roles after building 1–2 proofs |
| Student, no internship, with projects | `internships=0`, `projects>0` | Projects → Education → Campus → Skills | 1 | Projects, open-source, hackathons | `campus` / `modern` | Junior/intern roles in the project's domain; adjacent roles |
| Student with internship | `internships>0` | Experience → Projects → Education → Skills | 1 | Internship outcomes + projects | `ats-classic` / `campus` | Return offer, same-domain junior roles |
| New grad | `stage=new_grad` | Experience → Projects → Education | 1 | Internship + projects + GPA | `ats-classic` | Graduate programs, junior roles |
| Career switcher | `stage=switcher` | Summary → Transferable skills → Projects → Experience | 1–2 | Transferable evidence, new projects | `ats-classic` / `modern` | Adjacent roles, bridge roles, internal transfer |
| Experienced (3–9 yrs) | `full_time_years 3–9` | Experience → Selected projects → Skills → Education | 1–2 | Scope, impact, leadership | `ats-classic` / `editorial` | Same-function roles, one level up |
| Senior / manager (10+) | `full_time_years 10+` or `level=lead` | Summary → Experience → Selected achievements → Education | 2 | Business impact, team/scope, strategy | `executive` | Leadership roles, domain expert |
| Academic | `target=academia` | Education → Research → Publications → Teaching | 2+ | Publications, grants, talks | `academic` | Faculty, postdoc, research scientist |
| Creative | `role_family=design/creative` | Portfolio → Experience → Selected projects | 1 + portfolio | Portfolio, process, outcomes | `editorial` / `modern` | Design, brand, content roles |

> Page counts in this table are international defaults. For Chinese-market resumes, use **1–2 pages for students / <3 years** and **2–3 pages for 3+ years**, and apply the rules in `docs/cn-resume-rules.md` (core skills, AI-related ability, internship, project depth, CS fundamentals, primacy effect).

### 2.1 Chinese-market hard rules

The Chinese market has its own screening logic, not just a language switch. Before optimizing a Chinese resume, read `docs/cn-resume-rules.md`. The hard rules include:

- Four core signals: core skills, AI-related ability, internship, projects — order by strength.
- Never one-shot a full resume with generic AI prose.
- Never fill skills with AI buzzwords while omitting operating systems, networks, data structures, or databases.
- Never write demo-only projects; show the candidate's own changes, optimization, and thinking.
- Never omit school, degree, major, or dates; HR systems parse resumes automatically.
- Put key information early; put weaker information later (primacy effect).
- Campus interviewers skim for a highlight, then read in detail; blog/open-source links must be real and valuable.

## 5. Job recommendation rules

The system recommends **role families and fit tiers**, not a single "perfect job", and never a fabricated percentage.

### 5.1 Inputs

- Vault facts: education, experience, projects, skills, awards, languages.
- Preferences: market, city, role family, seniority, work authorization, constraints.
- Optional JD or job list.

### 5.2 Scoring

Borrow the offer-toolkit rubric, simplified:

```
Fit = 0.6 × MustHaveCoverage + 0.2 × NiceToHaveCoverage + 0.2 × TrajectoryFit
```

Each requirement is scored `1.0` (direct evidence + detail + recent), `0.5` (adjacent / claim without detail / older), or `0.0` (no evidence). A missing must-have caps the tier. Output a **tier**, not a precise score:

| Tier | Meaning |
|---|---|
| Strong fit | Direct evidence for nearly all must-haves |
| Worth applying | 1–2 gaps that can be closed by framing or a small project |
| Stretch | Structural gap or missing must-have; apply only with a referral or a plan |
| Not yet | Core must-haves absent; build evidence first |

### 5.3 Gap classification

- **Fixable in 30 days**: reframing, a portfolio case, a short course, a certification.
- **Hard to fix**: years of domain experience, leadership scale, degree, work authorization.
- **Not important**: boilerplate JD language, nice-to-haves not on the critical path.

### 5.4 Output

- 3–5 role families, ranked.
- For each: why it fits, evidence used, gaps, and a concrete next action.
- 1–2 stretch roles and 1 adjacent pivot.
- For candidates with thin evidence: a 2–4 week proof-building plan (project, open-source contribution, competition, freelance case).

## 6. What "suitable" means (the fit gate)

A resume is deliverable only when all six gates pass:

1. **Truth** — every claim traceable to the vault; no invented facts or metrics; no inflated ownership.
2. **Targeting** — the resume is a deliberate selection for a market, role, and persona, not a dump.
3. **Appropriateness** — follows the target market's conventions (photo, fields, page size, section order, language).
4. **Legibility** — 5-second scan, clear hierarchy, typography floor, no overflow.
5. **Parsability** — text extractable, standard headings, consistent dates, contact parseable.
6. **Differentiation** — at least one memorable, verifiable proof point per role.

If the facts are insufficient, the system must not fill the gap with plausible content. It switches to **build mode**: an honest starter resume plus a plan to acquire the missing evidence.

## Template language families

- **Chinese:** `campus`, `compact` (students/new grads), and `modern-sidebar` (experienced/switcher/senior). CJK-first font stacks, 1.5–1.55 leading, `YYYY.MM` dates.
- **English:** `ats-classic`, `campus`, `compact`, `modern-sidebar`, `editorial`, `executive`. Latin-only stacks, 1.3–1.4 leading, `YYYY-MM` dates.

Each template variant declares one language. Rendering and QA select the variant by `writing.locale`, falling back to the market profile's `language`; a missing or mismatched variant fails explicitly.
